# 약사 검수 안내 (블라인드)

OMNI-PHARM의 판정이 실제 약사의 판단과 얼마나 맞는지 재는 검수입니다. **프로그램의 판정은 보여 드리지 않습니다**(블라인드).
검수 결과는 프로그램의 첫 외부 검증이 됩니다. 지금까지의 검증은 모두 개발 측이 만든 문제로 한 것이라 이 검수가 가장 중요합니다.

## 누가, 얼마나
- **약사 2명 이상**(가능하면 3명). 약사끼리 얼마나 일치하는지가 프로그램이 도달할 수 있는 상한이므로 2명 이상이 필요합니다.
- 사례 200개(환자 6유형 × 흔히 쓰는 약 2~4개 조합). 한 사례에 30초~1분, 전체 약 2~3시간. 나눠서 해도 됩니다(자동 저장).

## 하는 법 A — 엑셀로 주고받기
1. 약사에게 **`docs/validation/약사_검수표_배포용.xlsx`**를 보냅니다(이메일·카카오톡). 프로그램 판정은 이 파일에 없습니다
   (숨긴 시트도 없음). 원본 `약사_검수표.xlsx`는 보내지 마세요 — 사례 목록 원본입니다.
   - '안내' 시트: 검수자 이름 칸(노란 칸), 판정 기준, 가정(통상 용량), 진행 건수가 자동으로 표시됩니다.
   - '환자' 시트: 6가지 환자의 나이·키·체중·크레아티닌·CrCl·eGFR·간 검사·질환.
   - '사례' 시트: 200개 사례(약 이름은 한글(영문)), '약사 판정' 칸은 목록에서 위험/주의/안전/모름을 고르면 색이 칠해집니다.
2. 돌려받은 파일을 **`docs/validation/검수결과/`** 폴더에 넣습니다(약사마다 한 파일, 파일 이름은 상관없음 — 검수자는 '안내' 시트의
   이름으로 구분).
3. 채점: `python scripts/score_review.py docs/validation/검수결과` (아래 '채점' 참고). 일부만 채운 파일도 채운 사례만 채점합니다.

배포용 파일은 사례 목록 원본에서 다시 만들 수 있습니다: `python scripts/review_sheet.py send`. (`python scripts/review_sheet.py`만
실행하면 **새 사례를 뽑아 원본을 덮어쓰므로** 검수를 시작한 뒤에는 하지 마세요.)

## 하는 법 B — 휴대폰 화면(/review)
1. 이 PC에서 `OMNI-PHARM 네트워크 공유 실행.bat`을 실행합니다(같은 와이파이의 휴대폰에서 접속 가능).
   PIN을 쓰려면 `.env`에 `OMNIPHARM_ACCESS_PIN=숫자`를 넣고 약사에게 알려 줍니다.
2. 약사는 휴대폰·PC 브라우저에서 `http://<이 PC의 IP>:8000/review`를 엽니다.
3. 검수자 이름(또는 코드, 예: 약사A)을 넣고 **시작**. 같은 이름으로 다시 열면 이어서 합니다.
4. 사례마다 환자 정보와 약을 보고 하나를 고릅니다.
   - **위험**: 함께 쓰지 않거나 처방 변경·용량 조절이 꼭 필요
   - **주의**: 함께 쓸 수 있으나 관찰·간격·환자 설명이 필요
   - **안전**: 특별한 조치 없음
   - **모름**: 판단 자료가 부족함(채점에서 제외)
5. 메모에는 판단 이유나 "프로그램이 이것을 알려야 한다"는 점을 적어 주세요(선택).

## 채점
```
python scripts/score_review.py
```
- 검수자별: 일치율, Cohen 카파(가중치 없음·선형 가중), '위험'의 민감도(약사가 위험이라 한 것을 프로그램도 위험이라 한 비율)와
  양성 예측도, 혼동행렬
- 검수자 사이: 쌍별 Cohen 카파, 전체 Fleiss 카파
- 프로그램 판정은 **채점할 때 현재 버전 엔진으로 다시 계산**합니다(검수표 엑셀의 옛 판정은 쓰지 않음).
- 결과: `logs/validation/review_score.json`, 불일치 사례는 `logs/validation/review_disagreements.csv`
- 엑셀로 받은 경우: `python scripts/score_review.py docs/validation/검수결과`(폴더 안 모든 .xlsx) 또는
  `python scripts/score_review.py 약사A.xlsx 약사B.xlsx`. 판정 칸의 공백·'비교적 안전'은 정리하고, 목록 밖의 글자는 건너뜁니다.

## 결과 읽는 법
- 카파 0.6 이상이면 '상당한 일치', 0.4~0.6 '중간', 0.4 미만 '낮음'(Landis & Koch). 약사끼리의 카파보다 높기는 어렵습니다.
- 가장 중요한 수치는 **'위험'의 민감도**(놓친 위험)입니다. 불일치 사례는 규칙을 고칠 근거가 되며, 고친 뒤에는 새 사례로
  다시 검수해야 합니다(같은 사례로 다시 재면 과적합).

## 개인정보
- 사례는 가상의 환자입니다. 검수 답은 이 PC의 `data/review/`에만 저장되고 밖으로 보내지 않습니다.
