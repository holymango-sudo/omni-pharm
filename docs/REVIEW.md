## 1. 치명적 문제 (동작 불가 / 잘못된 결과)

| # | 기존 상태 | 영향 | 조치 |
|---|---|---|---|
| 1 | `models/gnn.py`는 v2 구조(임베딩 테이블 방식)로 바뀌었는데 `api.py`는 옛 8-인자 호출을 그대로 사용 | **예측 API가 호출 즉시 오류** | `engine.py` 신설, API 전면 재작성 |
| 2 | `scripts/pipeline.py`가 존재하지 않는 모듈(`fda_labels`, `train_pair`, `train_patient`, `mol3d`)을 import | 파이프라인 중단 | 4개 모듈 모두 구현 |

| 4 | **환자 정보가 모델에 전혀 들어가지 않음** — 학습된 GNN은 약물 구조만 보고, 환자 상태는 임의의 배수(×1.25, ×1.6 …)를 곱하는 규칙 | 기획서 핵심("환자 상태 + 분자 구조를 동시에 분석")이 미구현 | FAERS 환자 단위 보고(나이·성별·체중·동반질환)로 **환자-다약제 모델** 학습 |

| 6 | 복용 시간대가 다르면 위험도 ×0.5 | 임상 근거 없음 | 제거 |
| 7 | LLM(EXAONE)이 근거에 없는 용량·약물명을 생성, 와파린 복용 환자에게 NSAID 대체 권고 | **환자 안전 위험** | 근거 기반 프롬프트 + 금지 규칙, 준수율이 높은 Qwen3-8B로 교체, LLM 장애 시 규칙 기반 리포트로 자동 대체 |

## 3. 데이터·모델 보완

- **학습 데이터 14배 확대**: v1은 상위 180종·1.2만 쌍 → v2는 PubChem 구조가 확인된 **1,602종·172,429쌍**
- **최신 약물 공백 해소**: TWOSIDES는 ~2014년까지의 자료라 팍스로비드(니르마트렐비르), 엔트레스토(사쿠비트릴), 에독사반, 우파다시티닙, 오시머티닙 등 최근 10년 약물이 전부 빠져 있었음 → FAERS 2015~2026에서 보고 1,500건 이상인 저분자 약물 **227종**을 PubChem 구조로 추가(`pipeline.py extend`, 바이오의약품·펩타이드는 규칙과 원자 수로 제외) → **총 1,829종**
- 한글 성분·제품명 추가: 팍스로비드, 엔트레스토, 릭시아나, 포시가, 자디앙, 브릴린타 등
- **FAERS 원자료** 2015Q1~최신 분기 다운로드·파싱(병렬 4개), 케이스 버전 중복 제거, 성분명 정규화(염·수화물 제거, 국제명 동의어: paracetamol→acetaminophen, divalproex→valproate 등)
- **평가 설계 강화**
  - 쌍 모델: 무작위 분할 + **처음 보는 약물**(검증용/테스트용 콜드 약물 분리, 모델 선택을 콜드 검증셋으로)
  - 환자 모델: **미래 시점 분할**(최근 4분기) + 처음 보는 약물 포함 보고
  - **비교 실험**: GNN vs Morgan 지문 vs 앙상블, 환자 정보 제거(ablation)
  - **환자 요인 민감도 분석**: 같은 약물에서 질환 하나만 바꿨을 때 장기별 위험 배수
  - 확률 보정 지표(ECE) 보고
- FDA 라벨 인덱스: 115종 → 1,296종 (Paxlovid처럼 substance 필드가 없는 복합제 라벨도 generic명 분해로 인식), **금기·박스경고** 섹션까지 검색, 단일성분 Rx 라벨 우선
- 영문 브랜드명 자동 인식(FDA 라벨의 brand_name → 성분)
- 동일 성분 중복(예: 타이레놀 + 아세트아미노펜 복합제) 감지

## 5. 기획서와 다르게 결정한 부분 (의도적)

| 기획서 | 결정 | 이유 |
|---|---|---|
| PostgreSQL, Neo4j | Parquet + 메모리 인덱스 | 데이터가 읽기 전용이고 수백 MB 규모 — DB 서버 2개를 띄우면 시연 장애 지점만 늘고 응답 속도 이득이 없음. 엔진 기동 ~10초, 예측 수십 ms |
| Llama 3 8B (vLLM) | Ollama + Gemma 4 12B (교체 가능) | Windows에서 vLLM 미지원. v2.5에서 이 PC 기준 5개 모델 벤치마크(`scripts/bench_llm.py`) 결과 gemma4:12b 채택(이전 qwen3:8b). `OMNIPHARM_LLM_MODEL`로 교체 가능 |
| DrugBank | PubChem + openFDA + TWOSIDES/FAERS | DrugBank는 라이선스(상업 이용 불가·계정 필요) 문제. 공개 데이터만으로 동일 기능 구현 |
| "확률 94%" 데모 문구 | 실제 모델 출력 그대로 표시 | 근거 없는 숫자를 보여주지 않음. 대신 "일반 대비 ×N배"로 위험 크기를 직관적으로 표현 |
| 인체 이미지(body.jpg) | SVG 장기 맵 직접 제작 | 기존 이미지에 "PATIENT STATUS: STABLE", "BPM 74" 등 **가짜 생체신호가 박혀 있어** 임상 화면에 부적절 |
